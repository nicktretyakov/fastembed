# Text Embeddings на Rust

Полный рабочий пример создания текстовых представлений (эмбеддингов) и семантического поиска на языке Rust.

Проект содержит **две версии**:

1. **TF-IDF** (чистый Rust, без внешних зависимостей) — работает сразу.
2. **Dense-эмбеддинги через fastembed** (нейросетевые sentence-transformers) — настоящие dense-векторы.

## Версия 1: TF-IDF (чистый Rust)

### Что это такое

**TF-IDF** (Term Frequency — Inverse Document Frequency) — классический способ представления текста в виде числового вектора.

- **TF (Term Frequency)** — как часто слово встречается в конкретном документе.
- **IDF (Inverse Document Frequency)** — насколько слово редкое во всей коллекции документов.
- Итоговый вес слова = `TF × IDF`.

Чем чаще слово в документе и чем реже оно в других документах — тем выше его вес.

### Как запускается

Просто:

```bash
cargo run --release
```

Внешних зависимостей нет. Компилируется даже на старых версиях Rust.

### Что делает программа

1. Берёт 6 предложений (про ML, животных, языки программирования).
2. Строит словарь всех уникальных слов.
3. Считает IDF для каждого слова.
4. Превращает каждое предложение в нормализованный вектор (L2-норма).
5. Считает косинусное сходство между всеми парами.
6. Выполняет семантический поиск по запросу.

### Пример вывода

```
=== Текстовые эмбеддинги (TF-IDF, чистый Rust) ===

Построение TF-IDF модели на 6 документах...
Размерность словаря: 34

=== Косинусное сходство (порог > 0.05) ===
0.088 | «Машинное обучение...» ↔ «Глубокое обучение...»
0.176 | «Глубокое обучение...» ↔ «Python популярен...»

=== Семантический поиск ===
Запрос: «Как компьютеры учатся на примерах данных?»

Топ-3:
1. [0.5053] Машинное обучение позволяет компьютерам учиться на данных.
2. [0.1915] Кошки любят спать на мягких подушках.
3. [0.0000] Глубокое обучение — это подмножество машинного обучения...
```

## Версия 2: Dense-эмбеддинги (fastembed)

### Что это такое

**Dense-эмбеддинги** — это плотные векторы фиксированной размерности (обычно 384 / 768), которые создаёт нейросеть. Они умеют улавливать **смысл** предложения, а не только совпадение слов.

Библиотека `fastembed` использует ONNX Runtime и предобученные модели из семейства sentence-transformers (например, `all-MiniLM-L6-v2`).

### Требования

- **Rust ≥ 1.88**
- Интернет при первом запуске (скачивается модель ~80–90 МБ)

### Как включить

1. В файле `Cargo.toml` раскомментируйте строку:

```toml
[dependencies]
fastembed = "7"
```

2. В файле `src/main.rs` замените функцию `main()` на код, который лежит в большом комментарии внизу файла (раздел «Версия с fastembed»).

3. Запустите:

```bash
cargo run --release
```

### Что делает программа (dense-версия)

1. Загружает предобученную модель `AllMiniLML6V2` (384 измерения).
2. Превращает каждое предложение в dense-вектор.
3. Считает косинусное сходство (теперь оно отражает семантическую близость).
4. Выполняет семантический поиск.

### Другие доступные модели

В коде можно заменить модель:

| Модель                      | Размерность | Особенности                          |
|----------------------------|-------------|--------------------------------------|
| `AllMiniLML6V2`            | 384         | Быстрая, хорошее качество (по умолчанию) |
| `AllMiniLML12V2`           | 384         | Точнее, чуть медленнее               |
| `AllMiniLML6V2Q`           | 384         | Квантизованная (быстрее, меньше памяти) |
| `MultilingualE5Small`      | 384         | Лучше работает с несколькими языками |
| `BGESmallENV15`            | 384         | Отлично подходит для поиска          |

## Как работает код

### 1. Токенизация

```rust
fn tokenize(text: &str) -> Vec<String> {
    text.to_lowercase()
        .split(|c: char| !c.is_alphanumeric() && c != '_')
        .filter(|s| !s.is_empty() && s.chars().count() > 1)
        .map(|s| s.to_string())
        .collect()
}
```

- Приводит текст к нижнему регистру.
- Разбивает по любым символам, кроме букв, цифр и `_`.
- Отбрасывает слишком короткие токены (1 символ).

### 2. Построение TF-IDF

```rust
impl TfIdfEmbedder {
    fn new(documents: &[&str]) -> Self { ... }
    fn embed(&self, text: &str) -> Vec<f32> { ... }
}
```

**В `new`:**
- Считается, в скольких документах встречается каждое слово (`doc_freq`).
- Строится словарь `слово → индекс`.
- Считается IDF: `ln(N / df) + 1`, где `N` — число документов.

**В `embed`:**
- Считается TF (частота слова в тексте / длина текста).
- Умножается на IDF.
- Вектор нормализуется (L2-норма), чтобы длина вектора была равна 1.

### 3. Dense-эмбеддинги (fastembed)

```rust
let model = TextEmbedding::try_new(
    TextInitOptions::new(EmbeddingModel::AllMiniLML6V2)
        .with_show_download_progress(true),
)?;

let embeddings = model.embed(documents, None)?;
```

- Модель скачивается автоматически при первом запуске.
- `embed` принимает список строк и возвращает `Vec<Vec<f32>>`.
- Каждый внутренний вектор имеет фиксированную длину (384).

## Косинусное сходство

```rust
fn cosine_similarity(a: &[f32], b: &[f32]) -> f32 {
    let dot: f32 = a.iter().zip(b.iter()).map(|(x, y)| x * y).sum();
    let norm_a: f32 = a.iter().map(|x| x * x).sum::<f32>().sqrt();
    let norm_b: f32 = b.iter().map(|x| x * x).sum::<f32>().sqrt();
    if norm_a == 0.0 || norm_b == 0.0 {
        0.0
    } else {
        dot / (norm_a * norm_b)
    }
}
```

Формула:

\[
\cos(\theta) = \frac{\mathbf{a} \cdot \mathbf{b}}{\|\mathbf{a}\| \cdot \|\mathbf{b}\|}
\]

- Значение от **−1** до **1**.
- **1** — векторы полностью совпадают по направлению.
- **0** — ортогональны (нет сходства).
- После L2-нормализации формула упрощается до простого скалярного произведения.

Именно по этому значению мы решаем, насколько два текста «похожи».

## Семантический поиск

Алгоритм:

1. Превращаем запрос в вектор (`query_emb`).
2. Считаем косинусное сходство запроса с каждым документом.
3. Сортируем результаты по убыванию сходства.
4. Берём топ-K (в примере — топ-3).

```rust
let mut results: Vec<(usize, f32)> = embeddings
    .iter()
    .enumerate()
    .map(|(i, emb)| (i, cosine_similarity(&query_emb, emb)))
    .collect();

results.sort_by(|a, b| b.1.partial_cmp(&a.1).unwrap_or(std::cmp::Ordering::Equal));
```

В случае dense-эмбеддингов поиск понимает смысл («компьютеры учатся» ≈ «машинное обучение»), даже если слова почти не совпадают.

В случае TF-IDF поиск в основном опирается на пересечение слов.

## Возможные улучшения

| Улучшение                        | Как сделать                                      |
|----------------------------------|--------------------------------------------------|
| Сохранять эмбеддинги на диск     | `serde` + `bincode` / `serde_json`               |
| Индекс для быстрого поиска       | HNSW (`usearch`, `hnsw`) или FAISS через FFI     |
| Батчинг больших коллекций        | Уже поддерживается в `fastembed`                 |
| Мультиязычность                  | Модель `MultilingualE5Small` / `BGE`             |
| Свои модели                      | Экспорт в ONNX → загрузка через `ort`            |
| Интеграция с векторной БД        | Qdrant, LanceDB, Chroma                          |
| Обучение своих эмбеддингов       | `linfa` + PCA / или обучение в Python → ONNX     |
